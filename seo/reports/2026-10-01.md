## Finding (not fixed this run — watchdog mode is report-only): the GitHub Pages deploy has been broken since 09-28

Issue **#20 "\[auto-alert\] site deploy is failing"** opened 2026-09-30
21:54 UTC and has failed on every run since (5 consecutive failures of
`.github/workflows/pages.yml`, all on commit `aaa07aa`, through
2026-10-01 20:33 UTC) — confirmed by reading each run's job logs via the
GitHub API this run, not inferred from the issue title. currentwire.us
itself is unaffected only because Pages has never successfully deployed yet
(DNS hasn't switched), so there is no "last good build" at risk today — but
the moment the owner flips DNS and switches Pages on, this is what the
hourly auto-deploy will hit.

**Root cause, confirmed by reproducing locally:** `pages.yml` sets
`NEXT_PUBLIC_SITE_URL: https://currentwire.us` at the workflow level so the
real static build gets the production URL. That same env var leaks into the
`Unit tests` step in the same job, which runs before the build. One test,
`tests/unit/news-sitemap.test.ts` line 90, hardcodes the pre-migration
assertion `<loc>http://localhost:3000/story/big-story-c1</loc>`, so it fails
whenever `NEXT_PUBLIC_SITE_URL` is set to anything else. `ci.yml` never sets
that var, so the regular CI workflow has stayed green the whole time — only
`pages.yml` ever exercises this path, which is why it sat undetected for 3
days. The neighboring `tests/unit/archive-sitemap.test.ts` already asserts
against `siteConfig.url` instead of a literal host; the one-line fix brings
`news-sitemap.test.ts` in line with that existing pattern.

Verified locally this run (not pushed, per the watchdog-mode rule to commit
and push only `seo/`/`data/` files today):
- Applying `<loc>${siteConfig.url}/story/big-story-c1</loc>` (importing
  `siteConfig` from `@/config/site`) makes the test pass both with and
  without `NEXT_PUBLIC_SITE_URL=https://currentwire.us` set — the exact
  boundary that broke.
- Full gate re-run with the fix applied: `npx vitest run` (1216 passed, 3
  skipped, 0 failed), `npx tsc --noEmit` (clean), `npx eslint app lib
  components config scripts tests` (0 errors, 1 pre-existing unrelated
  warning), `npx next build` (succeeds), and
  `node scripts/build-static-site.mjs` with
  `NEXT_PUBLIC_SITE_URL=https://currentwire.us` — the exact command
  `pages.yml` runs — succeeds end to end including its internal
  link/sitemap/RSS/llms.txt resolution check.
- The fix was reverted before committing, so nothing outside `seo/` changed
  in this run's push.

This is the first item for the next non-watchdog run (or the owner, if
faster): apply that one-line change to
`tests/unit/news-sitemap.test.ts:90`, run the same gates, push. It costs
nothing and unblocks the Pages pipeline before DNS switches.
