**The site's response to the outage was the part that was code, and it is
fixed.** Every archive read used to catch its own failure and return empty, so
"the query blew up" and "no such story" reached the callers as the same value —
and the callers turned that into a hard 404 on 1,322 URLs the site guarantees
will never 404, plus a cacheable 200 stating it had zero permanent story URLs.
Both of those outlive the outage that produced them. The daily loop shipped
`d060817` during this run: reads that decide whether a URL *exists* now raise
instead of returning empty, so the archive sitemap answers 503 and published
story URLs answer a retriable 5xx. Verified live after deploy.

That fix also turned the status code into a diagnosis, which is what makes the
owner action small: **503 means the archive is configured and not answering.** A
missing `DATABASE_URL` would have produced a 200 with an empty `<urlset>`
instead. So this is the Neon project, not a Vercel environment variable, and
nothing in the repository can restore it.

## Losses and unresolved, with cause

**The archive outage.** Cause: external — the Neon free-tier database stopped
answering. Owner action required; see the end of this report.

**Nothing routes a red monitor to a human, for the third time.** `seo-health`
and `url-survival` both went red within 20 minutes of each other on the first
morning of the outage. They were correct, they were early, and nothing acted on
either for about fifteen hours. This is the same failure recorded on 2026-08-17
and 2026-08-18 — the alarm is fine and the delivery does not exist. `gh` still
returns HTTP 403 on this repo's Actions logs, so the loops cannot even read the
failure they can see listed. `PLAYBOOK.md` no longer describes this alerting as
loud without saying what "loud" actually reaches.

**The measuring instrument was itself broken, quietly.** `cwv-check.mjs` picks
its story-page target as the first `/story/` entry in the URL ledger, with no
liveness check. During this outage that URL answered 500 with a 9,353-byte
error page, and the probe measured it and recorded `LCP 1,172 ms` in
`data/cwv-history.json` as a story-page vital. It looked entirely plausible —
1,172 ms is a good number, and nothing downstream distinguishes it from a real
one. Fixed this run and verified: the probe now skips non-200 candidates (it
skipped six, five 500s and a 504) and measures a live story, or reports two
surfaces instead of three and says why.

**`/news-desk` carries no JSON-LD** — the only one of the masthead trust pages
without it, and the one `NewsMediaOrganization.masthead` points at. Missed by
the 2026-08-19 clear-out, which typed the other six. Filed as backlog 4.

**Story pages 500 where the sitemap route 503s.** Both are retriable, so the
decisive property holds, but 503 with `Retry-After` is the documented signal.
Filed as backlog 2.

## Core Web Vitals

**PageSpeed Insights is still unavailable at $0, and this run re-confirmed it
rather than assuming it.** The keyless endpoint returned **HTTP 429** —
`Quota exceeded for quota metric 'Queries' and limit 'Queries per day'` — and
the CrUX API returned **HTTP 403**, "Method doesn't allow unregistered
callers". So there is no field data and no Lighthouse score, and none is
reported here.

What the keyless Chromium probe measured, under Lighthouse mobile throttling
(4× CPU, 1638.4 kbps, 150 ms), two runs about five minutes apart:

| Page | Run 1 LCP | Run 2 LCP | CLS | Probe TTFB |
|---|---|---|---|---|
| `/` | 6,344 ms | 7,172 ms | 0 | 2,842 / 2,858 ms |
| `/top-100` | 7,376 ms | 4,604 ms | 0 | 112 / 121 ms |
| story page | *(error page — discarded)* | 4,044 ms | 0 | 126 ms |

**These LCP numbers should not be read as a regression, and this report will
not claim one.** Two things disqualify them. `/top-100` moved 7,376 → 4,604 ms
between two runs five minutes apart with no deploy between them, which is
measurement noise larger than the effect anyone would want to detect. And the
probe reports 2,842 ms TTFB for `/` where curl, sampled five times with a
mobile Chrome user agent, measures **134–386 ms warm with `X-Vercel-Cache:
HIT`** — a twentyfold disagreement about the one metric both tools measure the
same way. When the instrument and a direct measurement disagree by 20×, the
instrument is the thing under suspicion.

What *can* be proven about performance this week, and is:

| Measurement | Value | Method |
|---|---|---|
| Warm TTFB, 5 page types | 120–155 ms, all HIT/PRERENDER | curl, 4 samples each |
| HTML transfer | 14–31 KB brotli (`/` ≈ 316 KB decoded) | curl with `Accept-Encoding` |
| Publisher images, `/` | 22 files, 1,758 KB, median 79 KB, max 144 KB | fetch + byte count |

Read plainly: TTFB, transfer weight, image weight and CLS are all in good shape
and all independently verified. LCP is unmeasured this week in any sense worth
quoting, and calling the probe's numbers a regression would be inventing a
finding. Making the keyless probe stable enough to trust is the honest next
step, and it is real work rather than a key purchase — a PSI key would only add
CrUX field data, which needs traffic volume this site does not yet have.

## Competitor content-gap snapshot

Structure taken from live robots.txt and sitemaps on 2026-08-20, plus web
search for what each competitor's most-linked assets actually are.

**Google News** exposes exactly three indexable hub families in robots.txt:
`/topics/`, `/publications/`, `/stories/`. It blocks seven AI crawlers by name
(CCBot, GPTBot, ChatGPT-User, PerplexityBot, anthropic-ai, ClaudeBot,
Claude-Web). Unchanged from 08-18.

**AllSides** publishes **7,011** sitemap URLs, up 6 from 7,005 on 08-18 — a
growth rate of about two URLs per day. The composition is the finding and it is
stable:

| Section | URLs | Share |
|---|---|---|
| `/news-source/*` | 3,698 | 52.7% |
| `/blog/*` | 2,440 | 34.8% |
| `/featured/*` | 698 | 10.0% |
| `/media-bias/*` | 9 | reference pages |

**Ground News** returned **403** to sitemap requests again. Its robots.txt
allows GPTBot explicitly and blocks AhrefsBot, YandexBot and image crawlers.
Search confirms its public identity is the per-story coverage-distribution page
plus the Blindspot feed — stories covered disproportionately by one side.

**CurrentWire today**: `sitemap.xml` 267 URLs — 200 story, 24 topic hubs, 13
source hubs, 4 methodology pages, and one each of the sections and trust pages.
Plus 2,793 permanent story URLs in the archive sitemap when it is answering.

Three evidence-based gaps:

1. **Publisher hubs are listing pages, not reference pages.** AllSides devotes
   **52.7%** of its entire URL inventory to `/news-source/*`. CurrentWire has
   13, and measured this run they are thin in *kind*, not just count:
   `/source/bbc-news` 634 words / 28 story links, `/source/npr` 280 / 10,
   `/source/the-verge` 250 / 10 — an ItemList and a BreadcrumbList over a list
   of stories, with no per-publisher facts. Cadence, category mix, tier
   rationale and first-seen date are all things the site already computes and
   none of them appear. The count is capped by the ingest feed list, but the
   *depth* is not capped by anything. **This is the largest content gap and it
   is unchanged from 08-18.**
2. **Evergreen reference content exists now, and is the smallest inventory on
   the board.** 35% of AllSides' URLs are non-perishable `/blog/*`, and search
   confirms its most-linked assets are reference pages
   (`/about/media-bias-rating-methods`, `/media-bias/media-bias-chart`) rather
   than news. CurrentWire went from **0 to 3** such pages on 08-19
   (792–1,195 words each, all parsing). This gap narrowed and did not close.
3. **Ground News's identity is per-story coverage distribution — CurrentWire
   has the field and gives it one page running 5 items.** `/most-covered` now
   exists, which was last week's finding. But breadth on this site is a lower
   bound limited to ingested publishers, so the differentiator is structurally
   shallow. The honest read: **do not chase bias ratings** — Ground News's
   left/centre/right split needs a bias dataset this site does not have, and
   inventing one would violate the no-fabricated-ratings rule outright.
   Breadth *depth* is the ground CurrentWire can actually take.

One competitive advantage worth keeping and now worth more: CurrentWire's
robots.txt allows every AI crawler where Google News blocks seven by name, and
`llms.txt` now documents the site's failure contract as well as its structure.

## Data quality

- **0 duplicate slugs** and **0 duplicate normalized titles** across 333
  news-sitemap entries.
- Publication dates all inside the window; oldest 48.07 h at fetch time against
  the health check's deliberate 49 h grace. The gap is the sitemap's own 5-minute
  edge cache, which is exactly what the grace was sized for.
- **One dedup recall miss**, recorded rather than filed: two clusters covering
  the FBI raid on Rep. Swalwell's home, published 70 minutes apart, one source
  each. This sits inside the designed contract — precision ≥ 0.98 is held far
  above recall ≥ 0.80 on purpose, because a wrong merge corrupts a story page
  while a missed merge only leaves two pages where one belonged. Worth noting
  that the low-confidence half landed in `/general`, which is noindexed, so
  Google sees one of the two. Not filed against `lib/news/` on one observation.
- No misclassification found in the crawl sample this run.
