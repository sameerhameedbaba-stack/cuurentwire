## 3. Shipped today — ISR was inert on every dynamic route (backlog item 2)

**The bug.** `/story/[slug]`, `/topic/[slug]`, `/source/[slug]` and
`/archive/[date]` each declared `export const revalidate`, with comments
explaining the ISR intent, and the cron's `ISR_SURFACES` list already called
`revalidatePath` on three of them. None of it did anything. Next 16 applies
ISR to a **dynamic** segment only when the page also exports
`generateStaticParams` — the bundled docs say so explicitly ("You must return
an empty array from generateStaticParams ... in order to revalidate (ISR)
paths at runtime"). Without it the routes land in the build's ƒ (Dynamic)
bucket, and production answered:

```
Cache-Control: private, no-cache, no-store, max-age=0, must-revalidate
X-Vercel-Cache: MISS
```

on **every** fetch, including two consecutive fetches of the same story URL
with no query string. That is 2,128 story URLs plus every topic hub, source
hub and archive day page rendering from scratch on each crawl.

**The fix** (commit `3e8397a`): each of the four exports
`generateStaticParams` returning `[]` — nothing prerendered at build (building
2,128 archived stories would blow up build time for pages read once a month),
every URL edge-cached on its first visit and refreshed by the cron's existing
`revalidatePath`. The build route table flips all four from ƒ to ● (SSG).

**Gates before push** — all green: `npx vitest run` 460 passed / 2 skipped;
`npx tsc --noEmit` clean; `npx eslint .` zero problems; `npm run build` exit 0;
`npx playwright test --workers=3` 59 passed / 1 skipped.
