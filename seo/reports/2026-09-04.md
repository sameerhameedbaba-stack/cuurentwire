## 4. What shipped

`0058fa6` — backlog **00b**, closed.

`scripts/vercel-ignore-build.sh` keeps `:(exclude)data` and ANDs a second diff
over `COMPILED_DATA_FILES`. The script still can only ever exit 0 or 1, the
rule that prevents a repeat of the 49-hour shipping deadlock.

**The interaction this change could have broken, and what was done about it.**
`deploy-watch.yml` decides which commit *should* have produced a deployment
record by mirroring the ignore script's pathspecs — that mirror is what stopped
`[auto-alert]` #9 from crying wolf yesterday. Widening the build rule without
widening the mirror would have made the watch stop expecting a record for a
commit Vercel does build: the same false-alarm class, in the other direction.
So `BUILD_INCLUDED_DATA_FILES` is mirrored alongside
`BUILD_EXCLUDED_PATHSPECS`, the watch now runs **two** git queries and takes
the newer answer (one pathspec set cannot express both halves — `:(exclude)data`
would hide the very files the second half is about), and **the existing drift
test now parses both lists out of the shell script**, so the mirror cannot rot
silently.

Two comments that asserted the opposite of reality are corrected rather than
deleted: `lib/seo/gsc-signals.ts`, and `.github/workflows/gsc.yml`, which
claimed the weekly commit "triggers a Vercel deploy — that is intended". It did
not, from 2026-08-24 until today.

## 5b. Also fixed: the Bluesky poster shared one story twice

The standing daily channel check (`bluesky-post.yml` green, posts landing on
the public API) found the runs green — 5 posts visible, one every ~5 h — but
**two of them are the same story**: "Gloria Steinem, trailblazing journalist and
activist, dies at 92" at 11:27 UTC and "Feminist icon Gloria Steinem dies at 92"
at 16:33 UTC. Both URLs end `-c6f6dcadc62b0`.

Dedup is stateless and reads the account's own feed, but it compared **URL
strings** — and a story slug is derived from its headline, so a rewrite makes
one story look like two. It costs a slot out of the ~8/day ceiling and shows
followers the same death twice.

Fixed by keying the ledger on the cluster id (`dedupKey`, in the new
`scripts/bluesky-post-lib.mjs`) — the same fix `archiveRowCacheKey` made for the
archive row cache on 2026-09-01, on the same verified property: every published
story slug ends with its own cluster id. A URL with no well-formed token keeps
its normalised URL as its key, so section pages and external links behave
exactly as before — the over-matching direction would silence the feed, which is
worse than a duplicate. Five tests, including a drift guard that parses
`CLUSTER_ID_RE` out of `lib/database/archive.ts`, since the poster runs under
plain node in CI and cannot import the TypeScript module.

Gates re-run for this change: **999 passed**, 3 skipped; `tsc` clean; eslint 0
errors; build success; playwright **119 passed**, 1 skipped.

**Not verified live yet**, and deliberately not claimed as such: the proof is
the absence of a duplicate across the next headline rewrite. Tomorrow's run
re-reads the feed.
